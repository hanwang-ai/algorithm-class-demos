Three key lines: set<int> s = {{...}} de-duplicates and sorts; set_intersection / set_difference / set_union all require sorted ranges and write through an inserter.

📄 Answers, complexity, pitfalls

1set.insert(v): duplicates ignored, order kept (red-black tree, O(log n) per insert)
2intersection: keep on equality, else advance the smaller side
3difference ds−os: keep ds-only values, skip both on a tie
4union: merge both runs, take equal values once

Complexity: inserting n elements is O(n log n); intersection / difference / union each scan both sorted ranges once, O(n+m).
Why two pointers? Because a set keeps its elements sorted — that is the key difference from unordered_set (fast de-duplication but unordered, so an intersection would need sorting or hashing first).

Pitfalls: (1) the output of set_intersection must be able to insert — passing both_courses.begin() will not compile, use inserter(...); (2) the direction of the difference matters — set_difference(ds, os) is "only Data Structures"; (3) all three algorithms require sorted inputs, so sort a vector first.
